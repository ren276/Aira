<threat_model>

## Trust Boundaries

| Boundary                                                | Description                                                                       |
| ------------------------------------------------------- | --------------------------------------------------------------------------------- |
| Local derived continuity state -> Supabase snapshot row | Derived-only local data crosses device/network boundary for continuity sync.      |
| Supabase snapshot row -> local restore path             | Remote snapshot data is reintroduced into local continuity state after reinstall. |
| Worker orchestration -> upload use-case                 | Background sync triggers network upload paths under retry conditions.             |

## STRIDE Threat Register

| Threat ID | Category | Component                  | Disposition | Mitigation Plan                                                                                         |
| --------- | -------- | -------------------------- | ----------- | ------------------------------------------------------------------------------------------------------- |
| T-10-01   | I        | ContinuitySnapshot payload | mitigate    | Enforce derived-only payload contract and add exclusion assertions for raw tables/rows.                 |
| T-10-02   | T        | Repository write path      | mitigate    | Use explicit field mapping and schema whitelist; reject unknown/raw fields in mapper.                   |
| T-10-03   | R        | Sync attempt tracking      | mitigate    | Persist attempt metadata and failure reason codes in ContinuitySyncState.                               |
| T-10-04   | D        | Backstop retry flow        | mitigate    | Use bounded retry/backoff and idempotent upload semantics to prevent retry storms.                      |
| T-10-05   | E        | Restore apply path         | mitigate    | Apply restore via deterministic mapping and transaction boundaries, not direct arbitrary object writes. |

</threat_model>
