# Phase 2 - Plan 3: Background Sync and WorkManager

## Goal
Establish the backend orchestration loop using WorkManager to periodically execute the ingestion UseCase.

## Tasks

```xml
<task>
  <read_first>
    - app/src/main/java/com/aira/health/domain/repository/HealthDataRepository.kt
  </read_first>
  <action>
    Create `IngestHealthDataUseCase.kt` in `app/src/main/java/com/aira/health/domain/usecase/`.
    This orchestrates the ingestion loop. 
    It queries the `HealthDataRepository` for the past 14 days initially (or since the last sync timestamp stored in DataStore).
    It then filters records, resolving conflicts if overlapping timestamps exist (favoring the record with the higher numeric confidence value).
    Finally, it deposits these into Room via the Room DAOs (simulated for now, pending Phase 1 resolution).
  </action>
  <acceptance_criteria>
    - File `IngestHealthDataUseCase.kt` is created.
    - Class invokes `repository.readHeartRate`, `repository.readSleepSessions`, etc.
  </acceptance_criteria>
  <requirements>DATA-01, DATA-02, DATA-03, DATA-04</requirements>
</task>

<task>
  <read_first>
    - app/src/main/java/com/aira/health/domain/usecase/IngestHealthDataUseCase.kt
    - app/src/main/AndroidManifest.xml
  </read_first>
  <action>
    Create `HealthSyncWorker.kt` extending `CoroutineWorker` in `app/src/main/java/com/aira/health/data/worker/`.
    Inject `IngestHealthDataUseCase` and execute it in `doWork()`.
    In the companion object, create `fun schedule(context: Context)` which enqueues a `PeriodicWorkRequest` configured for 30 minutes with a `NetworkType.NOT_REQUIRED` and `RequiresDeviceIdle` or general periodic polling.
    Create `BootReceiver.kt` extending `BroadcastReceiver` to reschedule the worker on device reboot.
    Add `<receiver android:name=".util.BootReceiver">` to `AndroidManifest.xml` reacting to `android.intent.action.BOOT_COMPLETED`.
  </action>
  <acceptance_criteria>
    - File `HealthSyncWorker.kt` exists.
    - `PeriodicWorkRequestBuilder` limits execution interval (e.g. 15-30m depending on strictness).
    - `BootReceiver.kt` exists and `AndroidManifest.xml` contains `<receiver>` declaration for `BOOT_COMPLETED`.
  </acceptance_criteria>
  <requirements>DATA-04</requirements>
</task>
```

## Verification
- Inspect `AndroidManifest.xml` for `BOOT_COMPLETED` permission and receiver.
- Compile worker classes to ensure `CoroutineWorker` suspend rules are met.

## Must Haves
- The synchronization is highly robust and recovers immediately after an Android system restart.
