### Pattern 1: NavHost decoupling and argument minimalism

**What:** Keep `NavController` in route layer; pass callbacks/IDs to screens. [CITED: https://developer.android.com/develop/ui/compose/navigation]  
**When to use:** All top-level tab and detail route transitions.  
**Example:**

```kotlin
composable("insights/{metricId}") { entry ->
    val metricId = entry.arguments?.getString("metricId") ?: return@composable
    MetricDetailRoute(metricId = metricId)
}
```

### Pattern 2: Modal sheet lifecycle ownership

**What:** Sheet visibility should be state-driven and removed from composition when hidden. [CITED: https://developer.android.com/develop/ui/compose/components/bottom-sheets]  
**When to use:** D-11 explanation content in detail screens.  
**Example:**

```kotlin
if (showExplanationSheet) {
    ModalBottomSheet(
        onDismissRequest = { showExplanationSheet = false },
        sheetState = rememberModalBottomSheetState()
    ) { /* 3-part content */ }
}
```

### Pattern 3: Draw-phase optimization for ring-heavy dashboards

**What:** Cache expensive draw objects and defer high-frequency reads to draw/layout phase. [CITED: https://developer.android.com/develop/ui/compose/graphics/draw/overview] [CITED: https://developer.android.com/develop/ui/compose/performance/bestpractices]  
**When to use:** Home rings, strain dial, stress radar, energy visuals.

## Common Pitfalls

### Pitfall 1: IA drift caused by legacy route aliases

**What goes wrong:** Planners treat `BODY` and `COACH` as canonical tabs and miss locked 5-tab IA.  
**Why it happens:** Existing constants and bottom nav labels encode pre-locking structure.  
**How to avoid:** Introduce IA-aligned route names in one migration slice and update tests atomically.  
**Warning signs:** `AiraRoutes.BODY`, `AiraRoutes.EAT`, `AiraRoutes.COACH` remain in top-level nav.  
Sources: [VERIFIED: app/src/main/java/com/aira/health/presentation/navigation/AiraRoutes.kt] [VERIFIED: .planning/phases/04-user-interface-dashboards/04-RESEARCH.md]

### Pitfall 2: Detail semantic mismatch hidden by visual progress

**What goes wrong:** Screens render but represent wrong metric semantics (`SLEEP -> EnergyBank`).  
**Why it happens:** Route mapping and visual implementation evolved independently.  
**How to avoid:** Enforce route->metric assertion tests before visual polishing tasks.  
**Warning signs:** `MetricDetailRoute` dispatches to non-matching detail composables.  
Sources: [VERIFIED: app/src/main/java/com/aira/health/presentation/dashboard/details/MetricDetailRoute.kt]

### Pitfall 3: Mock leakage through supplementary surfaces

**What goes wrong:** Production app ships fabricated predictions/corrections narratives.  
**Why it happens:** Supplementary screens were scaffolded with static text and never re-bound.  
**How to avoid:** Treat supplementary screens as primary integrity scope in this phase, not optional polish.  
**Warning signs:** literal forecast percentages and fixed correction statements in composables.
